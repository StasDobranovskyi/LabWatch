# Перевірки LabWatch

Один запуск збірки не підтверджує виконання UART, LED або датчиків. Результати 03.10.2026 є в [validation](validation/README.md). Тести ЛР2 ще не виконані.

## ЛР1

| Тест | Дія | Критерій / доказ |
|---|---|---|
| T01, FR-01 | `make clean`, переконатися, що build відсутня; `make build`; зберегти SHA256 ELF/HEX/BIN. Повторити. | Обидва exit code 0; три файли непорожні; SHA256 збігаються. Зберегти host/platform, компілятор, image ID та логи. На Mac пройдено. У VM ще потрібно. |
| T02, FR-02 | Запустити Wokwi, спостерігати Serial Monitor щонайменше 10 с. | `STM32C031C6 ready` після старту й послідовні `tick`. Перше значення може бути 0; це секунди uptime, не лічильник подій. Зберегти реальний лог. |
| T03, FR-03 | Одночасно спостерігати PA5 LED у Wokwi. | Чергування станів приблизно раз на секунду. Повний цикл близько 2 с. Для числового доказу виміряти PA5 Logic Analyzer у подальшій окремій перевірці; лише відеоспостереження не є точним вимірюванням. |

## ЛР2

| Тест | Вхід / порядок | Очікуваний результат |
|---|---|---|
| T04, FR-04 | Reset, `mode work`, `mode service`, `mode idle`, `mode bad`. | Початковий idle; кожна допустима команда дає запис переходу; остання повертає помилку без переходу. |
| T05, FR-05 | PIR → Simulate Motion; потримати OUT high, повторити після low. Зробити в кожному режимі. | Один INFO на фронт, немає ALARM, режим не змінюється. Виміряти від фронту OUT до UART, ціль ≤100 мс. |
| T06, FR-06 | AD0 low/high; відомі accel X/Y/Z та rotation X/Y/Z через контролери Wokwi. | Адреси 0x68/0x69, WHO_AM_I 0x68, правильні знаки й одиниці. За X=0,Y=0,Z=1g норма близька до 1g, вона не є ударом. |
| T07, FR-07 | Почати без еталона; виконати `calibrate` на спокої та окремо в work на повторюваному нормальному профілі 10 с. Спробувати калібрування з імпульсом. | Без еталона `calibration_required`; нормальні дані формують два різні еталони. Забруднений запис відхиляється за визначеним під час реалізації правилом. |
| T08, FR-08 | Повторити записаний робочий цикл 60 с. Потім подати механічний профіль з відхиленнями 0.9T, T, 1.1T, де T є реально отриманим порогом. | Нормальний цикл без ALARM. Кандидат удару за умовою `>T`; на рівності немає нової тривоги. Початковий імпульс для тесту ≥100 мс, коротший перевірити окремо на пропуск. Зберегти час реакції, ціль ≤100 мс. |
| T09, FR-09 | Змінити вектор g зі сталою нормою для нахилу 9° і 11°, утримувати 400/600 мс відносно еталона. Окремо задати короткий імпульс. | Для початкових 10°/500 мс тільки стійка понадмежова орієнтація дає instrument_motion. Короткий імпульс перевіряється незалежним правилом удару. |
| T10, FR-10 | LDR від темряви до світла й назад; значення біля двох відкаліброваних меж, утримання 100/300 мс. | Raw ADC у вибраному діапазоні; напрям зміни за моделлю AO; гістерезис запобігає повторним подіям біля межі, стан потребує 200 мс. Немає заяв про точні люкси. |
| T11, FR-11 | Один і той самий удар та світловий профіль у idle, work, service; вихід із service. | Класифікація за PRD; service дає INFO. Після виходу потрібна калібровка; рух оператора сам не дозволяє сервіс. |
| T12, FR-12 | PIR high, механічний імпульс і світлова зміна в одному часовому вікні. | Три записи з різними джерелами; INFO оператора не приховує ALARM. Послідовні номери, без втрати подій. |
| T13, FR-13 | Від'єднати SDA MPU6050 у тестовій схемі або задати неправильну адресу. Одночасно PIR/LDR. | ERROR MPU6050, інші події й heartbeat працюють. Кожна операція завершується за обмеженим таймаутом. LDR/PIR мають обмежену діагностику: постійний рівень не доводить справність. |
| T14, FR-14 | Після різних подій перевірити рядки UART та LED, потім reset. | Є всі поля й унікальний номер; LED відповідає правилам ЛР2. Після reset журнал і еталони в RAM втрачені, режим idle. |

Тести з T08/T09 використовують початкові критерії. Після вимірювання фону записати фактичні T, частоту, фільтр і версію прошивки в результатах, повторити межові сценарії. Відкриття кожуха в темряві не є позитивним тестом виявлення світла: очікується, що система може його пропустити.
